# Team up: multiplayer agents in Super Team (14 Oct 2026, proposed)

Yang asked for multiplayer agents that belong to Super Agents and Super Team, not a separate product, and simpler than
Claude's Dispatch (which is single-player: one person's phone hands work to their own computer, and only the result comes
back). Decision D30 in PLAN.md.

## What it is
One message, several people's agents. "@Asha build the API for T-22, I'll do the UI." Agent S splits the work, each
part goes into that person's own coding session under their rules, everyone watches the parts live, and Agent S writes
one combined answer when they're done.

## Built from what Super Team already has
| Step | Already there | New |
|---|---|---|
| Name teammates | the team's members (`/v1/team`) | @mention completion in the composer (desktop, phone) |
| Split the work | Agent S in Plan mode: `create_task` with an owner, `set_deadline` | a rule in Agent S's prompt: an @mention means one part per person; parts are numbered under the parent (T-22.1, T-22.2), so the board needs no new table |
| A part reaches a person | `prompt_session` → `POST /v1/prompts`: the owner's rules (off, ask each time, automatic; read only or edit; daily token limit), queued up to 7 days while their laptop is off, on record | none |
| The person says yes | `POST /v1/prompts/{id}/decide` (the owner's desktop: badge and toast) | the same yes on the owner's phone: their laptop puts incoming prompts in Needs you, beside its own agents' questions |
| Watch it happen | `session_prompt` (status and answer), the prompt's lifecycle: pending, approved, running, done | each `prompt_session` call in a chat drawn as a card per person, with its live status (desktop, phone) |
| One answer | the parts' answers (`session_prompt`), `git_diff` / `github_pr` for what changed | when every card is done, Agent S runs a short follow-up in the same chat: what each part did, what to merge first, what to test together |
| Progress | coding-agent hooks report per task; Agent S's estimate beside the agent's claim | the parent task shows its parts as lanes and one combined bar |

No new hub table: the turn that sent the prompts knows their ids, and the sender's laptop watches them.

## Keeping it simple (what made Dispatch feel heavy)
- No setup: teammates are already connected through Super Team; their rules already decide what may run.
- No new screen: it happens in a chat, from an @mention.
- You see each person's part as it runs, not only the end.

## Demo
Two laptops (the two test instances), one phone: the lead types one sentence on the phone; both laptops' agents start; the
owner approves from a notification; the chat shows two live cards; the board shows T-22 with two lanes; Agent S posts the
combined answer.
